# Claude에게 일 맡기기

[문서 목차](README.md) · [프로젝트 소개](../README.md)

PR을 맡기면 thync가 PR 저장소의 로컬 폴더에서 tmux 안의 Claude Code 세션을 시작하고, [Concord](https://github.com/arinyaho/concord) 플러그인의 작업을 실행합니다. 다른 사람의 PR은 `concord:review-until-approve`로 리뷰하고, 내 PR은 그 PR 하나에 대해 `concord:pr-to-merge`로 리뷰에 답하고 병합까지 챙깁니다. 설계와 그 이유는 [설계 문서](design/review-handoff.md)에 있습니다.

## 실행 조건

PR을 실행하는 머신(`reflex_host`를 주면 그 서버)에 다음이 있어야 합니다.

| 준비물 | 확인하는 방법 |
| --- | --- |
| `claude` CLI, 그리고 `sources`의 `claude_code` | 없으면 화면에 '맡긴 일' 칸이 보이지 않습니다 |
| `tmux`, `gh` | 맡길 때 확인합니다 |
| Claude Code에 설치된 Concord 플러그인의 `review-until-approve`, `pr-to-merge` 스킬 | `~/.claude/plugins/cache/*/concord/*/skills/`에서 찾습니다. 버전은 가리지 않고, 플러그인을 꺼 두었는지는 보지 않습니다 |
| PR 저장소의 로컬 클론 | `company_roots` 바로 아래 폴더(이름순), 그다음 알려진 세션 폴더 순서로 보고, `origin`이 PR 저장소와 정확히 같은 첫 클론을 씁니다. 그런 클론이 없을 때만 저장소 이름이 바뀌었는지 GitHub에 물어 옛 이름의 클론을 찾습니다. 서버는 시작할 때 `company_roots` 아래 클론의 현재 저장소 이름을 미리 물어 둡니다. `git@gh-work:owner/repo.git`처럼 SSH 설정의 별칭을 쓴 `origin`도 그 별칭의 `HostName`이 `github.com`이나 `ssh.github.com`이면 GitHub 저장소로 봅니다 |
| 실행 계정 | `mien`이 있으면 클론을 맡은 mien 프로필(`mien which`)로 실행합니다. 클론에 프로필이 없으면 `mien_profiles`에서 그 PR을 목록에 올린 프로필로 실행하고, 둘 다 없으면 시작하지 않습니다. `mien`이 없으면 서버 프로세스의 `gh` 계정을 씁니다 |
| `mien_profiles`를 쓰는 경우 | 클론에 프로필이 있으면 그 PR을 목록에 올린 프로필과 같아야 합니다. 어느 계정도 목록에 올리지 않은 PR은 맡기지 않습니다 |

하나라도 없으면 확인 창이 이유를 보여 주고, 세션을 시작하지 않으며 '맡긴 일' 기록도 남기지 않습니다.

## 화면에서 맡기기

1. 다음 중 하나로 PR을 고릅니다.
   - 오른쪽 패널의 리뷰 요청, 받은 리뷰, 보낸 리뷰 항목에서 '맡기기' 버튼을 누릅니다. 키보드로 버튼에 가서 Enter를 눌러도 됩니다.
   - 그 항목을 뇌에 끌어 놓습니다. 끄는 동안 뇌 회전이 멈추고 맨 아래 줄기(척수)가 빛나 놓을 곳을 알려 주며, 줄기 가까이 가면 더 밝아집니다. 줄기가 작아서 뇌 위 어디에 놓아도 맡깁니다.
   - 뇌 그래프의 PR 노드를 줄기에 끌어 놓거나, PR 칸반 카드를 '맡긴 일' 칸에 놓습니다.
2. 확인 창이 실행할 머신에서 확인한 저장소, PR, 작업, 실행 계정, 실행 위치, 허용 동작을 보여 줍니다.
3. 시작을 누르면 세션이 시작됩니다. 확인 창의 제목이 결과(맡겼어요, 시작하지 못했어요, 시작됐는지 알 수 없어요)로 바뀌고, 서버의 답을 보여 줍니다. 취소하면 아무것도 시작하지 않습니다.
4. 맡긴 세션이 도는 동안 오른쪽 패널의 그 PR 항목에는 '맡기기' 대신 '맡김'이 보입니다. 세션이 끝나면 다시 '맡기기'가 보이고 같은 PR을 다시 맡길 수 있습니다. 다른 서버가 실행하는 일은 그 서버에 연결되지 않은 동안 '맡기기'로 보입니다. 그때 다시 맡기면 연결되지 않았다는 답을 받습니다.

받은 리뷰 항목은 리뷰가 달린 내 PR을 맡깁니다. 같은 PR에 리뷰어가 여럿이어도 대상은 PR 하나입니다. 항목을 누르면 뇌에서 그 PR을 표시하고, '상세' 버튼은 상세 창을 엽니다.

## 작업과 허용 동작

| 대상 | 실행 계정 조건 | 작업 | 시작을 누르면 허용하는 동작 |
| --- | --- | --- | --- |
| 리뷰 요청 (다른 사람의 PR) | PR 작성자가 아님 | `concord:review-until-approve` | 리뷰 게시, 막는 지적이 없는 라운드의 승인. 작성자의 push와 답글을 기다리며 라운드를 되풀이합니다 |
| 받은 리뷰, 보낸 리뷰 (내 PR) | PR 작성자 | `concord:pr-to-merge` (`OWNER/REPO#N` 하나) | 리뷰 지적 수정, 커밋·push, 답글, 자동 리뷰어 스레드 resolve, 리뷰 재요청, PR 본문 수정, 뒤처진 브랜치 갱신, 병합 전 실패한 필수 검사 재실행, 조건을 채운 경우 이 PR 하나의 병합, 병합 뒤 실패한 작업 재실행과 이 PR이 가리키는 티켓의 상태 변경·댓글 |

- 실행할 머신이 PR 작성자와 상태를 그 계정으로 GitHub에서 다시 읽습니다. 계정이 조건에 맞지 않거나, PR이 닫혔거나, 내 PR이 초안이면 시작하지 않습니다. `pr-to-merge`는 초안을 아무 보고 없이 건너뜁니다.
- 내 PR의 시작 버튼은 그 PR 하나의 병합 허락입니다. 병합 조건은 `pr-to-merge` 스크립트가 판단합니다. 같은 저장소의 다른 PR은 읽기만 하고 평가하거나 병합하지 않습니다.
- 세션이 이 허락을 받아들이지 않으면 병합 없이 돌고, 병합할 수 있는 PR을 `ready`로만 알립니다. 세션에 접속해 병합을 허락하거나 직접 병합합니다.
- `pr-to-merge`는 클론에서 내 PR을 고칩니다. 같은 클론에서 다른 PR의 `pr-to-merge` 세션이 돌고 있으면 시작하지 않습니다.
- 확인 창을 연 뒤 실행 계정, 프로필, 작업이 바뀌면 시작할 때 거절합니다. 다시 맡기면 새로 확인합니다.

### 다른 사람의 PR: 신뢰 선언

Claude Code에서 `review-until-approve`의 Claude 리뷰어는 격리되지 않으므로, 사용자가 그 세션에서 이 PR이나 작성자를 믿는다고 직접 써야 리뷰를 시작합니다. 선언은 사용자가 쓴 말 그대로여야 하고, 다른 프로그램이 전한 글이나 고른 선택지는 선언이 아닙니다. 그래서 thync는 선언을 대신 쓰지 않습니다. 처음 맡기면 세션이 선언을 기다립니다. 아래 접속 명령으로 세션에 들어가 직접 씁니다. 선언 뒤 세션이 묻는 예/아니요 확인은 선택 질문이면 thync의 선택 대기 창에서 답해도 됩니다.

## 진행 상태 확인

세션은 tmux 세션 `thync-<소유자>-<저장소>-<번호>-<해시 6자>`에서 돕니다. 정확한 이름은 시작 메시지와 카드에 보입니다. 같은 PR은 이 이름 하나뿐이어서, 세션이 있는 동안 다시 맡기면 거절하고 접속 명령을 보여 줍니다.

```bash
tmux attach -t <카드에 보이는 세션 이름>
```

'맡긴 일' 카드는 다음 상태를 보여 줍니다. tmux 세션이 있는 동안은 접속 명령도 함께 보입니다.

| 상태 | 뜻 |
| --- | --- |
| 시작함 | tmux 세션은 있고 세션 기록은 아직 없습니다. Claude Code에서 처음 여는 폴더면 폴더 신뢰 질문에서 멈춰 있을 수 있으니 접속해서 확인합니다 |
| 작업 중 | Claude가 일하고 있습니다 |
| 답을 기다림 | 세션이 선택 질문을 기다립니다 |
| 대기 중 | Claude의 차례가 끝났습니다. 백그라운드에서 PR을 지켜보는 중이거나, 신뢰 선언 같은 입력을 기다립니다. 접속해서 확인합니다 |
| 끝남 | tmux 세션이 없고 Claude Code가 종료 코드 0으로 끝났습니다 |
| 실패 (종료 코드) | Claude Code나 `mien exec`가 0이 아닌 코드로 끝났습니다 |
| 끝남 (종료 코드 모름) | tmux 세션이 없고 종료 코드 파일도 없습니다 (tmux 세션을 직접 닫은 경우 등) |

대화형 세션은 작업이 끝나도(승인, 병합, 닫힘) 스스로 종료하지 않습니다. 세션에서 결과를 확인한 뒤 Claude Code를 끝내면 카드가 '끝남'이 되고, 같은 PR을 다시 맡길 수 있습니다.

기록은 `~/.thync/reflex.json`, 종료 코드는 `~/.thync/handoff/<세션 이름>.<시작 시각>.exit`에 남습니다. Concord의 진행 기록은 Concord가 따로 관리합니다.

## 권한 범위

세션은 PR 저장소의 로컬 폴더에서 `--permission-mode auto`로 돌고, `~/.thync`·`~/.ssh`·`~/.claude/settings.json`은 Read 도구에서 거부합니다. 범위와 위험은 [데이터와 보안](security.md#pr-위임의-권한-범위)에 설명합니다.
