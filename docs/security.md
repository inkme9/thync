# 데이터와 보안

[문서 목차](README.md) · [프로젝트 소개](../README.md)

thync는 수집한 작업 정보를 로컬 화면에 제공합니다. 외부 서비스 조회와 PR 위임 과정에서는 해당 서비스와 통신합니다. 아래에서 저장 위치, 접근 방식, 서비스별 쓰기 범위를 확인할 수 있습니다.

## 접근 토큰과 저장 위치

서버는 `THYNC_HOME`(기본 `~/.thync`) 디렉터리를 `0700`, 접근 토큰 파일을 `0600`으로 설정합니다. Jira·Notion 토큰 파일도 [설정 안내](configuration.md#jira와-notion-연결)에 따라 `0600`으로 만듭니다. 개인 경로·회사 설정·토큰·수집 데이터는 저장소 밖에 둡니다.

서버는 `127.0.0.1`에서 실행합니다. 정적 화면은 토큰 없이 제공하지만, `/graph.json`과 쓰기 요청은 `X-Thync-Token` 헤더가 서버 토큰과 일치해야 허용합니다. 같은 머신의 다른 사용자도 로컬 주소에 접속할 수 있고, [Tailscale로 접속](getting-started.md#tailscale로-접속하기)할 때는 tailnet 접근 규칙(ACL)이 허용한 모든 기기가 접속할 수 있으므로 토큰을 함께 확인합니다. 요청의 `Host`가 로컬 호스트 이름(`127.0.0.1`, `localhost`, `::1`)이나 `*.ts.net`인지도 검사해, 임의의 도메인을 이용한 DNS 리바인딩을 막습니다. `*.ts.net`은 Tailscale로 접속할 때의 주소입니다. 이 도메인의 공개 DNS는 Tailscale이 응답하지만, 신뢰할 수 없는 Wi-Fi처럼 DNS 응답을 조작할 수 있는 네트워크에서는 이 이름으로도 리바인딩이 가능하므로, 이때 데이터와 쓰기 요청을 막는 것은 접근 토큰입니다.

`tailscale_users`에 적은 Tailscale 로그인 이름은 토큰 대신 쓸 수 있고, 토큰과 같은 권한을 받습니다. `tailscale serve --bg <포트>`(HTTPS 프록시)는 요청에 접속한 사람의 로그인 이름을 `Tailscale-User-Login` 헤더로 붙이고, 클라이언트가 직접 보낸 같은 이름의 헤더는 지웁니다. Funnel로 들어온 요청과 태그가 붙은 기기의 요청에는 이 헤더가 붙지 않습니다. 이 헤더는 서버가 확인할 방법이 없으므로, 아래 경로로 들어온 요청은 목록의 사용자로 행세할 수 있습니다.

- 이 컴퓨터의 다른 프로세스: `127.0.0.1`로 직접 헤더를 보냅니다.
- 이 서버로 SSH 포트 포워딩을 연 컴퓨터: 허브의 `remotes` 연결과 손으로 연 `ssh -L` 모두 그 컴퓨터의 프로세스가 포워딩된 포트를 쓸 수 있습니다. 그 컴퓨터에서 아래 DNS 리바인딩이 일어나도 이 서버에 닿습니다.
- `tailscale serve --tcp`나 `--tls-terminated-tcp`로 연 경우: HTTP 헤더를 지우지 않으므로 tailnet 접근 규칙(ACL)이 허용한 모든 기기가 헤더를 보낼 수 있습니다.
- DNS 리바인딩: 이 컴퓨터가 DNS 응답을 조작할 수 있는 네트워크(신뢰할 수 없는 Wi-Fi 등)에 연결된 상태에서 이 컴퓨터의 브라우저로 악성 페이지를 열면, 그 페이지가 `*.ts.net` 이름을 `127.0.0.1`로 바꿔 이 헤더를 직접 보낼 수 있습니다. 공격자는 목록의 로그인 이름만 알면 됩니다.

그래서 `tailscale_users`는 혼자 쓰고, 믿을 수 있는 네트워크에만 연결하고, 다른 컴퓨터가 SSH 포워딩으로 붙지 않는 컴퓨터에서만 씁니다. 집에 둔 데스크톱이 이 경우입니다. 다른 기기의 브라우저가 이런 페이지를 열어도 그 기기의 `127.0.0.1`에는 thync가 없으므로 이 컴퓨터에는 닿지 않습니다.

토큰이 없거나 틀리면 화면 위쪽에 토큰 입력 칸이 나옵니다. 브라우저는 입력 칸이나 최초 접속 주소의 `#t=`에서 받은 토큰을 `localStorage`에 저장하고, `#t=`는 주소창에서 지웁니다. 토큰은 URL 쿼리에 넣지 않습니다. 원격 서버를 사용할 때는 [SSH 포트 포워딩](getting-started.md#원격-서버에서-실행하기)이나 [Tailscale](getting-started.md#tailscale로-접속하기)로 연결합니다.

## 데이터 흐름과 쓰기 범위

| 대상 | 읽거나 처리하는 내용 | 쓰기 범위 |
| --- | --- | --- |
| 로컬 파일 | 설정, 카드, 이름 변경, 위임 기록, 선택적으로 Claude Code·Codex 세션 로그 | 카드 편집·이름 변경·위임 상태 등을 `THYNC_HOME` 또는 설정한 카드 폴더에 저장합니다 |
| GitHub | `gh`로 내 커밋·리뷰 요청·내 PR을 조회합니다 | 사용자가 위임한 다른 사람의 PR에 리뷰와 선택적 승인을 게시합니다. 내 PR은 실행한 스킬이 수정·push할 수 있습니다 |
| Jira | 설정한 API로 티켓을 조회합니다 | 쓰지 않습니다 |
| Notion | 설정한 API로 페이지를 조회합니다 | 쓰지 않습니다 |
| Obsidian | `obsidian_vaults`에 적은 폴더의 `.md` 파일을 이 컴퓨터에서 읽습니다. 본문에서는 노트 링크, 태그, Jira 키, GitHub PR 주소만 뽑고 문장은 저장하지 않습니다. `obsidian_board`에 적은 Kanban 보드 파일 하나는 예외로, 카드의 글을 읽어 칸반에 보여 줍니다 | 쓰지 않습니다. 보드 카드는 thync에서 옮기거나 고칠 수 없습니다 |
| Claude CLI | PR 위임 시 PR 정보·diff 또는 로컬 저장소 내용을 처리합니다 | 외부 통신과 데이터 처리는 해당 CLI 설정과 서비스 정책을 따릅니다 |

Jira·Notion 요청은 리다이렉트를 따라가지 않아 토큰이 다른 호스트로 전달되는 것을 차단합니다. 출처별 수집 범위와 주기는 [설정 안내](configuration.md#수집-주기와-범위)에 설명합니다.

Obsidian 노트에서 그래프에 들어가는 정보는 vault 이름, vault 기준 경로, 파일의 절대 경로(노트를 여는 `obsidian://` 주소), 제목, 두 노트 이상이 함께 가진 태그, 본문에서 뽑은 Jira 키와 PR 주소입니다. 이 정보는 다음 경로로 나갑니다.

- `GET /graph.json`: 접근 토큰을 가진 사람이 봅니다.
- MCP 도구 `thync_now`와 세션 시작 hook: 집중 중이거나 진행 중인 노드의 이름, 작업 단위, 주소를 연결된 에이전트와 새 Claude Code 세션에 전달합니다.
- Jira: 노트 제목과 본문에 적힌 Jira 키를 설정한 Jira 서버에 조회합니다. Jira 토큰이 없으면 조회하지 않습니다.

`obsidian_board`를 설정하면 그 보드의 카드 글(제목 200자, 메모 4,000자까지, 200장까지), 카드가 속한 칸의 이름(100자까지)과 보드 파일의 절대 경로가 `GET /graph.json`의 `board`로 나갑니다. 접근 토큰을 가진 사람이 봅니다. MCP 도구 `thync_now`와 세션 시작 hook의 요약에는 보드 카드의 글이 들어가지 않습니다. 공유하거나 동기화하는 vault의 보드에는 다른 사람이 쓴 글이 있을 수 있으며, 화면은 카드 글을 글자로만 표시합니다.

vault 밖의 파일을 읽지 않도록 심볼릭 링크는 따라가지 않습니다. 보드 파일도 보통 파일일 때만 읽습니다.

## PR 위임의 권한 범위

| 대상 | 실행 방식 | 결과 |
| --- | --- | --- |
| 다른 사람의 PR | 임시 폴더에서 읽기 도구만 허용한 `claude -p --restricted`로 실행합니다 | thync가 받은 JSON을 검증해 GitHub 리뷰와 선택적 승인을 등록합니다 |
| 내 PR | 로컬 저장소의 tmux 세션에서 `--permission-mode auto`로 스킬을 실행합니다 | 스킬이 파일 수정·커밋·push 등 작업을 수행합니다 |

PR 본문이나 리뷰어 코멘트는 외부에서 작성한 입력입니다. 여기에 숨은 지시가 리뷰 문구와 승인 판단을 왜곡할 수 있습니다. 자동 승인 조건은 [위임 안내](handoff.md#자동-승인-조건)에서 확인할 수 있습니다.

내 PR에서 설정한 `Read(...)` 금지 목록은 해당 도구에 적용하는 제한입니다. 전체 프로세스를 격리하는 운영체제 샌드박스를 뜻하지 않습니다.

## 세션 로그 연동의 한계

Claude Code와 Codex 세션 로그는 공개된 형식이 아니므로 버전에 따라 읽기에 실패할 수 있습니다. 세션 로그를 사용하지 않으려면 `sources`에서 `claude_code`와 `codex`를 모두 제외합니다. `claude_code`를 제외하면 PR 위임 기능도 비활성화됩니다.
