# Obsidian Kanban 보드 읽기

## 동작

설정에 적은 Obsidian Kanban 보드 파일 하나의 카드를 thync 칸반에 읽기 전용으로 보여 줍니다. [Obsidian vault 출처](obsidian-source.md)와 같은 모듈(`thync/sources/obsidian.py`)이 읽고, 파일을 다루는 방식(링크를 따라가지 않음, 앞쪽 256KB만 읽음, 상대 경로를 받지 않음)도 같습니다.

### 보드는 하나, 읽기만

- 설정의 `obsidian_board`가 가리키는 파일 하나만 읽습니다. Obsidian에는 전역 보드를 하나만 둡니다. 보드 파일 여러 개를 읽거나 vault에서 보드를 찾지 않습니다.
- thync는 그 파일에 쓰지 않습니다. 카드를 옮기고 고치는 곳은 Obsidian입니다.
- 쓰지 않는 이유는 충돌입니다. Obsidian이 같은 파일을 열어 둔 채 다시 쓰고, 동기화 도구도 그 파일을 건드립니다. thync가 함께 쓰면 어느 쪽의 변경이 남을지 보장할 수 없습니다.

### 설정

```json
{
  "sources": ["claude_code", "codex", "github", "jira", "notion", "obsidian"],
  "obsidian_board": {"path": "~/vault/보드.md", "profile": "회사"}
}
```

- 값은 보드 파일의 경로이거나 `{"path": ..., "profile": ...}`입니다.
- `profile`은 `회사` 또는 `개인`입니다. 생략하거나 다른 값을 쓰면 `개인`입니다.
- `path`는 절대 경로나 `~`로 시작하는 경로여야 합니다. `obsidian_vaults`에 적은 vault 안에 있지 않아도 됩니다.
- 상대 경로, 사용자가 없는 `~사용자`, 경로가 아닌 값은 서버를 켤 때 버리고 서버 로그에 경고합니다.
- 경로에 NUL이나 UTF-8로 나타낼 수 없는 문자가 있으면 서버를 켤 때 버리고 경고합니다. 그대로 두면 요청마다 `lstat`이 오류를 내거나, 카드의 경로를 JSON으로 보내지 못합니다.
- `sources`에 `obsidian`이 없으면 읽지 않습니다.

### 읽는 범위

- 보통 파일만 읽습니다. 심볼릭 링크, 폴더, FIFO 같은 특수 파일은 읽지 않습니다.
- 앞쪽 256KB까지만 읽고, 그 안에서 끝난 줄까지만 씁니다.
- 내용이 UTF-8이 아니면 카드가 없습니다. 파일 맨 앞의 바이트 순서 표시(BOM)는 무시하고, `\r\n` 줄바꿈도 읽습니다.
- 머리말(맨 앞의 `---`로 감싼 부분)에 `kanban-plugin` 키가 있어야 보드로 봅니다. 값은 따지지 않습니다.
- `## 제목` 줄이 칸입니다. 칸 이름은 100자(`MAX_LANE`)까지 씁니다.
- 칸 아래에서 들여 쓰지 않은 `- [ ] 글`, `- [x] 글`, `- 글` 줄이 카드입니다. 글 없이 `- [ ]`만 있는 줄은 카드가 아닙니다. 첫 칸보다 앞에 있는 줄은 카드가 아닙니다.
- 카드 뒤의 들여 쓴 줄(빈 줄이 아닌 것)은 그 카드에 이어 붙입니다. 여러 줄 카드입니다.
- `%% kanban:settings`로 시작하는 줄이나 줄 맨 앞의 `***` 줄이 나오면 거기서 끝냅니다. 앞의 것은 플러그인의 설정이고, `***` 뒤는 보관함입니다.
- 그 밖의 줄은 건너뜁니다.
- 카드는 보드에 적힌 순서대로 앞의 200장까지만 씁니다.

### 읽는 시점과 파일을 여는 방법

요청 때 읽습니다. vault 노트처럼 배경 스레드를 두지 않습니다. 읽는 대상이 파일 하나이고 256KB로 잘라 읽으므로 비용이 작습니다.

요청마다 다음 순서로 합니다.

1. 경로를 `lstat`합니다. 보통 파일이 아니면(링크, 폴더, FIFO 등) 카드 없음으로 끝냅니다.
2. `lstat` 결과에서 열쇠 `(st_mtime_ns, st_ctime_ns, st_size, st_ino, st_dev)`를 만듭니다. 보관해 둔 열쇠와 같으면 파일을 열지 않고 보관한 결과를 돌려줍니다. 화면이 2초마다 요청하므로 대부분의 요청은 여기서 끝납니다.
3. 다르면 `O_RDONLY | O_NOFOLLOW | O_NONBLOCK`으로 엽니다. `lstat`와 여는 사이에 파일이 링크로 바뀌면 열리지 않고, FIFO로 바뀌어도 요청이 멈추지 않습니다.
4. 연 파일을 `fstat`해서 보통 파일인지 다시 확인하고, 256KB + 1바이트를 읽습니다. 256KB를 넘으면 마지막 줄바꿈 뒤를 바이트 단계에서 버린 다음에 UTF-8로 해석합니다. 해석을 먼저 하면 한글 한 글자의 가운데에서 잘린 큰 보드를 "UTF-8 아님"으로 잘못 봅니다.
5. 해석한 결과를 2의 열쇠와 함께 보관합니다. "보드가 아님"(머리말에 키 없음, UTF-8 아님)도 빈 결과로 보관합니다. 경로를 잘못 적은 경우에 요청마다 파일을 다시 읽지 않게 하기 위해서입니다.
6. 열기나 읽기가 실패하면(파일 핸들 부족, 그 사이에 링크·폴더·FIFO로 바뀜, 입출력 오류) 카드 없음으로 끝내고 아무것도 보관하지 않습니다. 파일이 바뀌지 않아도 다음 요청에서 다시 시도합니다. 오류는 `board_cards()` 밖으로 나가지 않습니다.

- 보관한 카드는 요청 스레드들이 함께 쓰므로 고치지 않습니다. `board_cards()`는 매번 사본을 돌려주고, `build_board()`는 카드 파일을 적용하는 반복문이 끝난 뒤에 보드 카드를 더합니다.
- 카드를 Obsidian에서 옮기면 다음 요청(2초 안)에 thync 칸반에 반영됩니다.

### 카드

`GET /graph.json`의 `board`에 다른 카드와 같은 모양으로 들어갑니다.

| 항목 | 값 |
| --- | --- |
| `id` | `obsidian-card:` + 카드 글의 SHA-1 앞 12자. 아래 "카드의 id" |
| `title` | 카드 첫 줄이 `**굵은 글**`로 시작하면 그 굵은 글, 아니면 첫 줄. 마크다운 표시를 걷어 내고(아래 "치르는 비용") 연속한 공백을 하나로 줄입니다. 200자까지. 글자나 숫자가 하나도 남지 않으면 `(제목 없음)` |
| `note` | 굵은 글 제목 뒤에 첫 줄에 남은 글(앞의 `—`, `–`, `-`, `:`, `·`, 공백은 뺍니다)과 이어 붙인 줄들. 줄마다 마크다운 표시를 걷어 냅니다. 4,000자까지 |
| `column` | 아래 "칸을 정하는 규칙" |
| `tags` | 칸 이름(100자까지), `Obsidian`. 카드마다 자기 칸의 이름을 가집니다 |
| `profile` | 설정의 `profile` |
| `updated` | 보드 파일의 수정 시각(초). 모든 카드가 같은 값입니다 |
| `readonly` | `true` |
| `url` | `obsidian://open?path=` + 보드 파일의 절대 경로를 퍼센트 인코딩한 값(`urllib.parse.quote(path, safe="")`). vault 노트의 `url`과 같은 방식입니다 |
| `file` | 보드 파일의 경로 |
| `sub`, `focus` | 빈 문자열 |
| `auto_column`, `moved` | `column`과 같은 값, `false` |

- 블록 id(줄 끝의 ` ^abc`)는 카드의 첫 줄과 마지막 줄에서 뺍니다. 플러그인은 블록 id를 카드 전체 글의 끝에 붙이므로, 한 줄 카드에서는 첫 줄, 여러 줄 카드에서는 마지막 줄에 있습니다.
- 블록 id는 `id`, `title`, `note` 어디에도 들어가지 않습니다. 플러그인이 붙이는 표식이고 사람이 읽을 글이 아니기 때문입니다.
- 카드 안의 날짜와 태그는 해석하지 않고 글자로 둡니다.

### 카드의 id

`obsidian-card:` + 카드 글의 SHA-1 앞 12자입니다. 여기서 카드 글은 체크 표시(`[ ]`, `[x]`)와 블록 id를 뺀, 이어 붙인 줄을 포함한 전체 글입니다. 연속한 공백은 하나로 줄이고, 마크다운 표시를 걷어 내거나 길이 상한으로 자르기 전의 글을 씁니다.

- Kanban 플러그인의 카드에는 id가 없습니다. 위치로 id를 만들면 카드를 옮길 때마다 id가 바뀌고, 글로 만들면 칸을 옮겨도 같은 카드로 남습니다. 화면이 id로 카드를 찾으므로 옮겨도 유지되는 쪽을 골랐습니다.
- 체크 표시와 블록 id를 빼므로 카드를 체크하거나 플러그인이 블록 id를 붙여도 id가 유지됩니다.
- 글이 같은 카드는 나온 순서대로 `-2`, `-3`을 붙여 구분합니다.
- 접두어는 `obsidian:`이 아니라 `obsidian-card:`입니다. vault 노트의 노드와 그 카드가 `obsidian:` id를 쓰므로, 보드 카드에는 서버가 접두어만 보고 쓰기 요청을 거부할 수 있는 따로 된 접두어가 필요합니다.

### 칸을 정하는 규칙

규칙은 코드에 고정합니다(`board_column`). 칸 이름을 소문자로 바꾸고 글자와 숫자가 아닌 문자(밑줄 포함)에서 끊어 낱말로 나눈 뒤, 위에서부터 처음 맞는 것을 씁니다. 낱말이 통째로 같아야 맞습니다(`미완료`는 `완료`가 아닙니다).

1. 카드가 체크되어 있으면(`- [x]`, `- [X]`) `done`
2. 플러그인이 완료 칸으로 표시한 칸이면 `done`. 표시는 칸 제목과 그 칸의 첫 카드 사이에 있는, 굵은 글(`**…**`)만으로 된 한 줄입니다. 사이에 빈 줄이 있어도 됩니다
3. 낱말에 `완료`, `완료됨`, `종료`, `done`, `complete`, `completed`, `closed`가 있으면 `done`
4. 낱말에 `진행`, `진행중`, `대기`, `막힘`, `확인`, `검수`, `doing`, `progress`, `blocked`, `waiting`, `review`가 있으면 `doing`
5. 그 밖은 `todo`

- 보드 카드는 `waiting`(선택 대기)과 `reflex`(맡긴 일) 칸에 들어가지 않습니다. 두 칸은 thync가 세션과 리뷰로 정하는 칸입니다.
- 범용 템플릿의 여섯 칸은 `1. 수집함`과 `2. 다음 할 일`이 `todo`, `3. 진행 중`·`4. 대기 / 막힘`·`5. 확인 / 검수`가 `doing`, `6. 완료`가 `done`입니다.

### 읽기 전용을 지키는 곳

화면만 막아서는 부족합니다. 카드의 칸과 글, 그리고 보드 파일 자체를 바꿀 수 있는 경로를 모두 막습니다.

| 경로 | 막는 방법 |
| --- | --- |
| 화면에서 끌기, 편집, 다른 칸에 놓기 | 카드에 `readonly`가 있으면 `draggable`을 끄고 편집을 붙이지 않습니다. 놓기 처리도 놓인 카드가 `readonly`이면 아무것도 하지 않습니다. 끌어 온 자료의 id를 그대로 믿지 않기 위해서입니다 |
| `POST /board`, `POST /rename` | 실제로 쓰게 될 id의 접두어를 보고 400으로 거부합니다. 그래프를 다시 만들지 않고 판정합니다. 칸, 제목, 메모, 되돌리기 모두 해당합니다. `POST /board`에 `new`가 있으면 서버는 요청에 든 `id`를 쓰지 않고 새 `manual:` id를 만들므로 거부 대상이 아닙니다 |
| `cards_dir`의 카드 파일 | `id`가 `obsidian-card:`로 시작하는 파일은 `build_board()`가 무시합니다. 보드 카드의 칸, 제목, 메모를 바꾸지 않고, 직접 추가한 카드로도 나오지 않습니다 |
| `save_card()`가 고른 파일이 카드 파일이 아닌 경우 | 쓰거나 지우려는 경로에 이미 Kanban 보드 파일이나 UTF-8이 아닌 파일이 있으면 거부합니다(`ValueError`, 요청은 400). `read_cards()`가 이런 파일을 건너뛰므로, 막지 않으면 카드 id에서 계산한 파일 이름이 그 파일과 같을 때 통째로 덮어쓰거나 지웁니다. thync가 쓴 카드 파일을 편집기가 다른 인코딩으로 다시 저장한 경우가 여기에 해당합니다 |

### 다른 기능과의 관계

- **노트 수집에서 뺍니다.** 보드 파일은 카드를 옮길 때마다 수정 시각이 바뀌어 늘 "최근에 고친 노트"가 됩니다. 노트로도 두면 보드 자체가 노드와 카드로 한 번 더 나오고, 카드 글 속의 링크와 Jira 키가 노트의 것으로 뽑힙니다. `obsidian.scan()`이 보드 파일을 건너뜁니다.
  - 같은 파일인지는 경로 문자열이 아니라 장치와 inode 번호(`st_dev`, `st_ino`)로 비교합니다. vault 경로가 링크를 거치거나 한글 파일 이름의 유니코드 정규화가 달라도 같은 파일을 알아보기 위해서입니다.
- **카드 파일 수집에서 뺍니다.** Kanban 보드 파일을 카드 파일로 읽으면 보드의 모든 카드 글이 카드 하나의 메모가 되고, 그 카드를 옮기면 `save_card()`가 머리말을 다시 써서 `kanban-plugin` 줄이 지워집니다. 그래서 `read_cards()`는 머리말에 `kanban-plugin` 키가 있는 파일을 건너뛰고, `save_card()`는 그 파일을 덮어쓰거나 지우지 않습니다.
  - 이 규칙은 `obsidian_board`를 설정하지 않아도 적용합니다. 설정하지 않은 보드 파일도 같은 방식으로 망가질 수 있기 때문입니다.
  - thync가 쓰는 카드 파일의 머리말에는 `id`, `title`, `column`, `profile`, `manual`만 들어갑니다(`store.py`의 `CARD_KEYS`). thync가 한 번이라도 다시 쓴 파일에는 `kanban-plugin` 키가 남아 있을 수 없으므로, 이 키가 있는 파일은 thync가 만든 카드 파일이 아닙니다. 파일 맨 앞에 BOM이 있어도 같은 판정을 합니다.
  - 사람이 카드 파일에 이 키를 직접 적어 둔 경우에는 그 카드가 사라집니다. 건너뛴 파일은 서버 로그에 알립니다. 파일 경로마다, 서버가 켜져 있는 동안 한 번입니다.
  - 보드를 읽는 쪽과 카드 파일을 읽는 쪽이 같은 판정 함수(`util.is_kanban`)를 씁니다. 두 쪽의 머리말 해석이 달라서 한 파일이 보드로도 보이고 카드 파일로도 다시 쓰이는 일이 없게 합니다.
  - 보드가 `cards_dir` 안에 있어도 보드 카드는 한 번씩만 나옵니다.
- **UTF-8이 아닌 카드 파일도 건너뜁니다.** `cards_dir`의 `.md` 파일 하나를 해석하지 못해 `GET /graph.json` 전체와 모든 `POST /board`가 실패하지 않게 하기 위해서입니다. Kanban 보드와 똑같이 서버 로그에 알리고 덮어쓰거나 지우지 않습니다. 건너뛰기만 하고 덮어쓰기를 막지 않으면, 카드 id에서 계산한 파일 이름이 같은 쓰기가 그 파일을 지웁니다.
- **에이전트 요약에 들어가지 않습니다.** MCP 도구 `thync_now`와 세션 시작 hook의 요약은 "맡긴 일" 칸의 카드만 쓰고, `GET /status.json`은 칸반 카드를 쓰지 않습니다.
- **뇌 그림의 노드가 되지 않습니다.** 보드 카드는 칸반에만 있습니다.

### 눌렀을 때

- 보드 카드에는 뇌 그림의 노드가 없으므로(`focus`가 비어 있음) 다른 카드처럼 노드로 갈 수 없습니다. 대신 카드의 `url`로 Obsidian에서 보드 파일을 엽니다.
- 무엇을 열지는 `web/src/card.ts`의 `opens()`가 정합니다. 카드가 `readonly`이고 주소가 `web/src/link.ts`의 `linkKind`로 `app`(`obsidian://open?`으로 시작)일 때만 그 주소를 돌려줍니다.
- `web/src/board.ts`는 그 주소를 `location.href`에 넣습니다. 브라우저가 주소를 Obsidian에 넘기고, 페이지는 그대로 남습니다. 탭을 열지 않는 이유는 vault 노트 링크와 같습니다. 탭을 열면 빈 탭만 남습니다.
- 두 번 누르기의 둘째 누름(`e.detail`이 2 이상)은 무시합니다.
- 데스크톱 앱(`desktop/src-tauri/src/main.rs`)의 thync 창은 webview가 `obsidian://` 주소를 스스로 열지 못하므로, 창 안에서 이동하려는 주소를 `on_navigation`에서 가로채 macOS의 `open` 명령으로 Obsidian에 넘깁니다. 창 자체는 이동하지 않습니다.

### 구조

| 위치 | 하는 일 |
| --- | --- |
| `thync/config.py` | `parse_board()`가 `obsidian_board`를 `{path, profile}`로 해석합니다. 상대 경로, NUL이나 UTF-8로 나타낼 수 없는 문자가 있는 경로, 쓸 수 없는 값은 버리고 경고합니다 |
| `thync/sources/obsidian.py` | `board_cards()`가 보드 파일을 읽어 카드 목록을 돌려줍니다. 형식 해석(`parse_board`)과 칸 규칙(`board_column`)은 파일을 열지 않는 함수로 떼어 둡니다. `scan()`이 보드 파일을 노트에서 뺍니다 |
| `thync/board.py` | `build_board()`가 끝에 보드 카드를 더합니다. `obsidian-card:`로 시작하는 카드 파일은 적용하지도, 직접 추가한 카드로 내놓지도 않습니다 |
| `thync/util.py` | `BOARD_CARD`(`obsidian-card:`)와 `is_kanban(text)`: 머리말에 `kanban-plugin` 키가 있는지 판정합니다. 보드를 읽는 쪽과 카드 파일을 읽는 쪽이 같은 함수를 씁니다 |
| `thync/store.py` | `read_cards()`가 Kanban 보드 파일과 UTF-8이 아닌 파일을 건너뜁니다. `save_card()`는 그런 파일을 덮어쓰거나 지우지 않습니다 |
| `thync/server.py` | `POST /board`와 `POST /rename`이 `obsidian-card:`로 시작하는 id를 400으로 거부합니다 |
| `web/src/types.ts` | `ApiCard`의 `readonly`와 `url` |
| `web/src/card.ts` | 카드를 끌거나 고칠 수 있는지(`editable`), 다른 칸에 놓을 수 있는지(`droppable`), 눌렀을 때 무엇을 여는지(`opens`) 정하는 함수. DOM 없이 테스트합니다(`web/test/card.test.ts`) |
| `web/src/board.ts` | 위 함수의 결과대로 카드를 만들고, 놓기 처리에서도 같은 함수로 거릅니다 |
| `desktop/src-tauri/src/main.rs` | thync 창이 `obsidian://` 주소로 이동하려 하면 macOS의 `open` 명령으로 넘깁니다 |

- `sources`에 `obsidian`이 있는지는 `build_board()`가 보드 카드를 더하기 전에 확인합니다.
- 잘린 마지막 줄을 버리는 일은 `_read_board()`가, 200장 상한과 칸 이름 100자 상한은 `parse_board()`가 합니다.

## 요청보다 오래 남는 상태

보드 기능이 읽고 쓰는, 한 번의 요청보다 오래 남는 자료는 다음과 같습니다.

- 보드 파일 읽기 결과의 보관(`obsidian.py`의 모듈 변수 `_board`)
- 보드를 빼는 노트 훑기 결과의 보관(`obsidian.py`의 `_notes`)
- 건너뛴 파일을 이미 알렸는지의 기록(`store.py`의 `_skipped`)
- 읽기 전용으로 지켜야 하는 `cards_dir`와 `names.json`

| 상태 | 사건 | 결과 | 증거 |
| --- | --- | --- | --- |
| 보관 없음 | 첫 요청 | 파일을 읽어 카드를 돌려주고, `lstat`에서 만든 열쇠와 함께 보관 | `test_a_card_on_the_board_is_a_readonly_card` |
| 보관 있음 | 파일이 그대로인 채 다시 요청 | 파일을 열지 않고 같은 카드를 돌려줌 | `test_an_unchanged_board_is_not_read_again` |
| 보관 있음 | 파일을 고친 뒤 요청 | 다시 읽어 새 카드를 돌려줌 | `test_an_edited_board_shows_on_the_next_request` |
| 보관 있음 | 파일이 사라지거나 링크, 폴더, FIFO로 바뀐 뒤 요청 | 카드 없음. 요청이 멈추지 않음 | `test_a_board_that_vanished_or_is_not_a_regular_file_gives_no_cards`, `test_a_file_swapped_for_a_fifo_after_the_listing_does_not_block` |
| 보관 있음 | 머리말의 `kanban-plugin` 키가 지워지거나 내용이 UTF-8이 아니게 된 뒤 요청 | 카드 없음. 빈 결과를 보관 | `test_a_file_that_is_no_board_gives_no_cards` |
| 보관 없음 또는 열쇠가 다름 | 열기나 읽기가 실패 | 카드 없음. 보관하지 않음. 파일이 그대로여도 다음 요청에서 다시 읽음 | `test_a_read_that_failed_is_tried_again_on_the_next_request`, `test_a_file_swapped_for_a_link_or_a_folder_after_the_listing_is_not_read` |
| 보관 있음 | 요청이 돌려받은 카드를 고침 | 보관한 카드는 그대로. 다음 요청은 고치기 전 값을 받음 | `test_the_kept_cards_are_not_shared_with_the_caller` |
| 보관 있음 | 두 요청이 동시에 다시 읽음 | 각자 읽은 결과를 자기 열쇠와 함께 한 번의 대입으로 보관. 열쇠(`lstat`)와 내용(읽기) 사이에 파일이 바뀌면 옛 열쇠에 새 내용이 묶일 수 있으나, 다음 요청에서 열쇠가 달라 다시 읽음 | 테스트 없음. 일부러 그 순간에 파일을 바꾸는 테스트를 만들 수 없어, 위 "파일을 고친 뒤 요청"으로 다시 읽기만 확인 |
| 노트 훑기 결과 | vault 안에 보드 파일이 있는 채로 훑음 | 보드 파일은 결과에 없음. 다른 노트는 그대로 | `test_the_board_file_is_not_scanned_as_a_note` |
| 카드 id에서 계산한 파일 이름이 Kanban 보드와 같음 | `POST /board` (쓰기, 되돌리기) | 400. 보드 파일 변화 없음 | `test_saving_a_card_never_overwrites_a_kanban_file` |
| `cards_dir`에 UTF-8이 아닌 `.md` | 요청 | 그 파일을 건너뛰고 나머지 카드는 그대로 | `test_a_card_file_that_is_not_utf8_is_skipped` |
| 카드 id에서 계산한 파일 이름이 UTF-8이 아닌 파일과 같음 | `POST /board` (쓰기, 되돌리기) | 400. 그 파일 변화 없음 | `test_saving_a_card_never_overwrites_a_file_it_could_not_read` |
| 건너뛴 파일의 알림 기록 | 같은 파일을 다시 건너뜀 | 알리지 않음. 서버를 다시 켜면 한 번 더 알림 | 테스트 없음. 로그 한 줄의 중복 여부이고 다른 동작에 영향이 없음 |
| 보드 카드 | `POST /board` (칸, 제목, 메모, 되돌리기) | 400. `cards_dir` 변화 없음 | `test_the_board_api_refuses_a_board_card` |
| 보드 카드 | `POST /rename` | 400. `names.json` 변화 없음 | `test_the_rename_api_refuses_a_board_card` |
| `cards_dir`에 `id: obsidian-card:…` 파일 | 요청 | 보드 카드는 그대로, 그 파일은 카드로 나오지 않음. 파일은 그대로 남음 | `test_a_card_file_cannot_change_a_board_card` |
| `cards_dir` 안의 보드 파일 | 요청, 그리고 그 파일 이름으로 만든 `manual:` id에 대한 `POST /board` | 카드로 나오지 않음. `POST /board`는 새 카드 파일을 만들 뿐 보드 파일을 건드리지 않음 | `test_a_board_inside_the_card_folder_is_not_a_card_and_is_left_alone` |
| 보통 카드 파일 | 요청 | 카드로 읽음 | `tests/test_store.py`의 테스트 |

## 치르는 비용

- **카드 글을 고치면 다른 카드가 됩니다.** id가 글에서 나오므로, Obsidian에서 글을 고친 카드는 thync에서 새 카드로 보입니다. 보드 카드에는 thync 쪽에 남는 정보(직접 옮긴 칸, 메모)가 없어서 잃는 것은 없습니다.
- **칸 규칙이 코드에 고정되어 있습니다.** 낯선 이름의 칸은 모두 Todo로 갑니다. 원래 칸 이름을 카드의 태그로 표시하므로 어느 칸의 카드인지는 보입니다. 규칙을 설정으로 바꾸는 방법은 없습니다.
- **칸 이름은 낱말 단위로 비교합니다.** 글자가 일부만 겹치는 이름(`미완료`, `Incomplete`, `미확인`)을 완료나 진행 중으로 잘못 보지 않기 위해서입니다. 대신 규칙에 없는 활용형(`끝냄`, `finished`)은 Todo로 갑니다.
- **"대기 / 막힘"은 진행 중으로 봅니다.** thync의 "선택 대기" 칸은 세션이 내 답을 기다릴 때만 쓰는 칸이라 보드 카드를 넣지 않습니다.
- **완료 칸 표시는 글자를 따지지 않습니다.** 플러그인은 완료로 표시한 칸의 제목과 첫 카드 사이에 굵은 글 한 줄을 적는데, 그 글이 Obsidian의 언어에 따라 다릅니다(영어 `**Complete**`, 한국어 `**완료됨**`). 그래서 그 자리에 굵은 글만 있는 줄이 있으면 완료 칸으로 봅니다. 사용자가 그 자리에 다른 굵은 글을 직접 적어 둔 보드에서는 잘못 판정합니다.
- **보드를 고치면 보드 카드가 한꺼번에 위로 올라옵니다.** 보드 카드의 `updated`는 모두 보드 파일의 수정 시각이고 화면은 그 순서로 정렬하므로, Obsidian에서 카드 한 장을 옮기면 최대 200장이 thync의 다른 카드 위에 놓입니다.
- **완료한 카드가 계속 보입니다.** 화면의 기간 선택은 보드 카드에 적용되지 않습니다. 보드에서 지우거나 보관함으로 보내야 사라집니다.
- **저장하는 순간에는 보드 카드가 잠깐 사라질 수 있습니다.** Obsidian이 파일을 고쳐 쓰는 도중에 읽으면 머리말이 없거나 잘린 내용을 읽습니다. 다음 요청에서 돌아옵니다.
- **카드를 한 번 누르면 Obsidian이 앞으로 나옵니다.** 글자를 고르려고 누른 경우도 같습니다.
- **긴 칸 이름은 잘립니다.** 칸 이름은 그 칸의 모든 카드에 태그로 붙으므로 100자까지만 씁니다. 100자 뒤만 다른 두 칸은 태그가 같아 보입니다. 칸을 정하는 규칙도 자른 이름으로 판정합니다.
- **카드 글의 마크다운은 일부만 걷어 냅니다.** 굵게(`**`), 취소선(`~~`), 기울임(`*`), 강조(`==`) 표시와 노트 링크·삽입(`[[노트]]`, `[[노트|이름]]`, `![[그림]]`)은 글자만 남깁니다(`[[노트|이름]]`은 `이름`). 밑줄로 쓴 기울임(`_글_`), 일반 링크(`[글](주소)`), 코드, 목록 기호는 그대로 보입니다.
- **`*`와 `==`는 앞뒤가 낱말과 떨어져 있을 때만 표시로 봅니다.** `2*3*4`나 `a==b==c`의 연산 기호를 지우지 않기 위해서입니다. 그래서 `*기울임*을`처럼 조사가 바로 붙은 기울임은 기호가 그대로 보입니다. `**`와 `~~`는 어디에 있든 걷어 냅니다. 한 쌍의 기호 사이가 300자를 넘으면 강조로 보지 않습니다. 닫히지 않은 기호가 많은 긴 줄에서 찾는 시간이 길어지지 않게 하기 위해서입니다.
- **보관함 표시는 줄 맨 앞의 `***`만 봅니다.** 카드 안에 들여 쓴 `***`는 카드의 글입니다.
- **카드 안의 날짜, 태그는 글자로 그대로 보입니다.** 해석하지 않습니다.
- **`x`와 `X`만 완료 표시로 봅니다.** 플러그인은 다른 문자의 체크 상태도 허용하지만, 그 뜻은 사용자마다 달라서 완료로 단정하지 않습니다.

## 남는 위험

- **카드 글, 칸 이름, 보드 파일의 경로가 나갑니다.** [vault 출처](obsidian-source.md)는 본문 문장을 저장하지 않지만, 보드 카드의 글은 보여 줄 내용 자체이므로 예외입니다. 카드 글, 칸 이름, 보드 파일의 절대 경로(`url`, `file`)가 `GET /graph.json`의 `board`로 접근 토큰을 가진 사람에게 보입니다. `thync_now`와 세션 시작 hook의 요약에는 보드 카드의 글이 들어가지 않고, 이 점은 테스트(`test_the_summary_for_agents_leaves_the_card_text_out`)로 지킵니다.
- **남이 쓴 글일 수 있습니다.** 공유하거나 동기화하는 vault의 보드에는 다른 사람이 쓴 카드가 있을 수 있습니다. 화면은 카드 글을 글자로만 넣고(`textContent`), 서버는 카드 글을 명령이나 경로로 쓰지 않습니다.
- **고친 것을 놓칠 수 있는 경우가 남습니다.** 카드를 옮기거나 체크하는 일은 파일 크기를 바꾸지 않아서, 바뀌었는지는 사실상 수정 시각으로 알아봅니다. 시각을 1~2초 단위로만 기록하는 파일 시스템(exFAT, SMB)에서 같은 초 안에 두 번 고치거나, 동기화 도구가 내용을 바꾸고 수정 시각을 되돌리면, 다음에 다시 고칠 때까지 옛 카드가 보입니다. 열쇠에 `st_ctime_ns`와 `st_ino`를 넣어 이런 경우를 줄입니다.
- **플러그인 형식을 일부만 확인했습니다.** 읽는 규칙은 플러그인의 parser와 언어 파일을 읽고 정했습니다. 실제 플러그인이 쓴 보드 가운데 보관함, 완료 칸 표시, 여러 줄 카드, 체크된 카드가 있는 보드로는 확인하지 않았으므로, 그 규칙들은 읽은 플러그인 코드만을 근거로 합니다. 읽지 못하는 줄은 건너뜁니다.
- **화면에서 확인한 범위가 좁습니다.** Playwright로 띄운 Chromium 브라우저에서 확인한 것은 다음과 같습니다.
  - 보드 카드는 끌 수 없습니다(`draggable="false"`).
  - 두 번 눌러도 편집이 열리지 않습니다.
  - 보드 카드를 다른 카드 위로 끌어 놓아도 쓰기 요청이 나가지 않습니다.
  - 누르면 카드의 `obsidian://open?path=` 주소로 이동을 요청합니다.
  - Chromium은 한 페이지에서 외부 프로토콜 주소를 한 번만 실행하므로, 같은 페이지에서 두 번째로 눌렀을 때는 이동을 다시 요청하지 않았습니다. 브라우저의 동작이며, 같은 페이지에서 카드를 다시 눌러도 Obsidian이 앞으로 나오지 않을 수 있습니다.
- **Obsidian이 실제로 열리는지는 확인하지 않았습니다.** 브라우저에서 누른 주소를 Obsidian이 여는지, 데스크톱 앱에서 카드를 누르는 경우 모두 직접 해 보지 않았습니다.
- **상위 폴더가 심볼릭 링크로 바뀌는 경우는 막지 못합니다.** vault 출처와 같은 한계입니다.
