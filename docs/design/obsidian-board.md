# Obsidian Kanban 보드 읽기

이슈: [#9](https://github.com/inkme9/thync/issues/9). [Obsidian vault 출처](obsidian-source.md) 위에 쌓습니다.

무엇을 읽고 카드의 각 항목에 무엇을 넣는지, 칸을 어떻게 정하는지는 이슈 #9의 "범위"가 기준입니다. 이 문서는 그렇게 정한 이유와 구조, 치르는 비용, 남는 위험을 적습니다.

## 결정

### 보드는 하나, 읽기만

- 설정의 `obsidian_board`가 가리키는 파일 하나만 읽습니다. 저장소 소유자가 Obsidian에 전역 보드를 하나만 두기로 정했습니다.
- thync는 그 파일에 쓰지 않습니다. 카드를 옮기고 고치는 곳은 Obsidian입니다.
- 쓰지 않는 이유는 충돌입니다. Obsidian이 같은 파일을 열어 둔 채 다시 쓰고, 동기화 도구도 그 파일을 건드립니다. thync가 함께 쓰면 어느 쪽의 변경이 남을지 보장할 수 없습니다.

### 구조

| 위치 | 하는 일 |
| --- | --- |
| `thync/config.py` | `obsidian_board`를 `{path, profile}`로 해석합니다. 상대 경로와 쓸 수 없는 값은 버리고 경고합니다 |
| `thync/sources/obsidian.py` | `board_cards()`가 보드 파일을 읽어 카드 목록을 돌려줍니다. 형식 해석(`parse_board`)과 칸 규칙(`board_column`)은 파일을 열지 않는 함수로 떼어 둡니다 |
| `thync/board.py` | `build_board()`가 끝에 보드 카드를 더합니다. `obsidian-card:`로 시작하는 카드 파일은 적용하지도, 직접 추가한 카드로 내놓지도 않습니다 |
| `thync/store.py` | `read_cards()`가 머리말에 `kanban-plugin` 키가 있는 파일을 건너뜁니다 |
| `thync/server.py` | `POST /board`와 `POST /rename`이 `obsidian-card:`로 시작하는 id를 400으로 거부합니다 |
| `web/src/card.ts` (새 파일) | 카드를 끌거나 고칠 수 있는지, 눌렀을 때 무엇을 여는지 정하는 함수. DOM 없이 테스트합니다 |
| `web/src/board.ts` | 위 함수의 결과대로 카드를 만듭니다 |

### 읽는 시점

요청 때 읽습니다. vault 노트처럼 배경 스레드를 두지 않습니다.

- 읽는 대상이 파일 하나이고 256KB로 잘라 읽으므로 비용이 작습니다. vault 전체를 훑는 일과 다릅니다.
- 파일의 수정 시각과 크기가 지난번과 같으면 파일을 열지 않고 지난번 결과를 돌려줍니다. 화면이 2초마다 요청하므로 대부분의 요청은 `lstat` 한 번으로 끝납니다.
- 카드를 Obsidian에서 옮기면 다음 요청(2초 안)에 thync 칸반에 반영됩니다.

### 카드의 id

`obsidian-card:` + 카드 글의 SHA-1 앞 12자입니다.

- Kanban 플러그인의 카드에는 id가 없습니다. 위치로 id를 만들면 카드를 옮길 때마다 id가 바뀌고, 글로 만들면 칸을 옮겨도 같은 카드로 남습니다. 화면이 id로 카드를 찾으므로 옮겨도 유지되는 쪽을 골랐습니다.
- 글이 같은 카드는 나온 순서대로 `-2`, `-3`을 붙여 구분합니다.
- 접두어를 `obsidian:`이 아니라 `obsidian-card:`로 둔 이유는 두 가지입니다. 서버가 접두어만 보고 쓰기 요청을 거부할 수 있어야 하고, #8이 "`obsidian:`으로 시작하는 카드가 없다"를 기준으로 삼기 때문입니다.

### 읽기 전용을 지키는 곳

화면만 막아서는 부족합니다. 카드의 칸과 글을 바꾸는 경로가 세 가지 있고, 셋 다 막습니다.

| 경로 | 막는 방법 |
| --- | --- |
| 화면에서 끌기와 편집 | 카드에 `readonly`가 있으면 끌기와 편집을 붙이지 않습니다 |
| `POST /board`, `POST /rename` | id의 접두어를 보고 400으로 거부합니다. 그래프를 다시 만들지 않고 판정합니다 |
| `cards_dir`의 카드 파일 | `id`가 `obsidian-card:`로 시작하는 파일은 `build_board()`가 무시합니다 |

### 보드 파일을 다른 수집에서 빼는 이유

- **노트 수집**: 보드 파일은 카드를 옮길 때마다 수정 시각이 바뀌어 늘 "최근에 고친 노트"가 됩니다. 노트로도 두면 보드 자체가 노드와 카드로 한 번 더 나오고, 카드 글 속의 링크와 Jira 키가 노트의 것으로 뽑힙니다. `obsidian.scan()`이 `obsidian_board`의 경로를 건너뜁니다.
- **카드 파일 수집**: 보드가 `cards_dir` 안에 있으면 지금은 `read_cards()`가 그것을 카드 하나로 읽고, 그 카드를 옮기면 `save_card()`가 보드의 머리말을 다시 써서 `kanban-plugin` 줄을 지웁니다. 머리말에 `kanban-plugin` 키가 있는 파일은 어떤 경우에도 thync의 카드 파일이 아니므로 건너뜁니다. 이 규칙은 `obsidian_board`를 설정하지 않아도 적용합니다. 설정하지 않은 보드 파일도 같은 방식으로 망가질 수 있기 때문입니다.

### 눌렀을 때

보드 카드에는 뇌 그림의 노드가 없으므로(`focus`가 비어 있음) 눌러도 갈 곳이 없습니다. 대신 `url`(`obsidian://open?path=<보드 파일>`)을 엽니다. 주소가 `web/src/link.ts`의 `linkKind`로 `app`일 때만 열고, 탭을 만들지 않고 브라우저에 넘깁니다.

## 상태가 있는 변경

이 변경이 읽고 쓰는, 한 번의 요청보다 오래 남는 자료는 보드 파일 읽기 결과의 보관(`obsidian.py`의 모듈 변수)과, 읽기 전용으로 지켜야 하는 `cards_dir`·`names.json`입니다.

| 상태 | 사건 | 결과 | 종류 | 증거 |
| --- | --- | --- | --- | --- |
| 보관 없음 | 첫 요청 | 파일을 읽어 카드를 돌려주고, 수정 시각·크기와 함께 보관 | 새로 생김 | `test_a_card_on_the_board_is_a_readonly_card` |
| 보관 있음 | 파일이 그대로인 채 다시 요청 | 파일을 열지 않고 같은 카드를 돌려줌 | 새로 생김 | `test_an_unchanged_board_is_not_read_again` |
| 보관 있음 | 파일을 고친 뒤 요청 | 다시 읽어 새 카드를 돌려줌 | 새로 생김 | `test_an_edited_board_shows_on_the_next_request` |
| 보관 있음 | 파일이 사라지거나 링크로 바뀐 뒤 요청 | 카드 없음. 보관을 비움 | 새로 생김 | `test_a_board_that_vanished_or_became_a_link_gives_no_cards` |
| 보관 있음 | 두 요청이 동시에 다시 읽음 | 둘 다 같은 파일을 읽어 같은 결과를 보관. 어느 쪽이 남아도 같음 | 새로 생김 | 테스트 없음. 보관하는 값이 파일 내용만의 함수이고 한 번의 대입으로 바꾸므로 따로 잠그지 않음 |
| 보드 카드 | `POST /board` (칸, 제목, 메모, 되돌리기) | 400. `cards_dir` 변화 없음 | 새로 생김 | `test_the_board_api_refuses_a_board_card` |
| 보드 카드 | `POST /rename` | 400. `names.json` 변화 없음 | 새로 생김 | `test_the_rename_api_refuses_a_board_card` |
| `cards_dir`에 `id: obsidian-card:…` 파일 | 요청 | 보드 카드는 그대로, 그 파일은 카드로 나오지 않음. 파일은 그대로 남음 | 새로 생김 | `test_a_card_file_cannot_change_a_board_card` |
| `cards_dir` 안의 보드 파일 | 요청, 그리고 그 파일을 가리키던 `manual:` 카드에 대한 `POST /board` | 카드로 나오지 않음. `POST /board`는 새 카드 파일을 만들 뿐 보드 파일을 건드리지 않음 | 바뀜 | `test_a_board_inside_the_card_folder_is_not_a_card_and_is_left_alone` |
| 보통 카드 파일 | 요청 | 지금과 같음 | 그대로 | `tests/test_store.py`의 기존 테스트 |

## 치르는 비용

- **카드 글을 고치면 다른 카드가 됩니다.** id가 글에서 나오므로, Obsidian에서 글을 고친 카드는 thync에서 새 카드로 보입니다. 보드 카드에는 thync 쪽에 남는 정보(직접 옮긴 칸, 메모)가 없어서 잃는 것은 없습니다.
- **칸 규칙이 코드에 고정되어 있습니다.** 낯선 이름의 칸은 모두 Todo로 갑니다. 원래 칸 이름을 카드에 표시하므로 어느 칸에서 왔는지는 보입니다.
- **"대기 / 막힘"은 진행 중으로 봅니다.** thync의 "선택 대기" 칸은 세션이 내 답을 기다릴 때만 쓰는 칸이라 보드 카드를 넣지 않습니다.
- **카드 안의 날짜, 태그, 블록 id는 글자로 그대로 보입니다.** 해석하지 않습니다.
- **`x`와 `X`만 완료 표시로 봅니다.** 플러그인은 다른 문자의 체크 상태도 허용하지만, 그 뜻은 사용자마다 달라서 완료로 단정하지 않습니다.

## 남는 위험

- **카드 글이 나갑니다.** [vault 출처](obsidian-source.md)는 본문의 문장을 내보내지 않는다고 정했고, 보드 카드의 글은 그 예외입니다. `GET /graph.json`의 `board`로 접근 토큰을 가진 사람에게 보입니다. `thync_now`와 세션 시작 hook의 요약은 "맡긴 일" 칸의 카드만 쓰므로 보드 카드의 글이 들어가지 않습니다. 이 점은 테스트로 지킵니다.
- **남이 쓴 글일 수 있습니다.** 공유하거나 동기화하는 vault의 보드에는 다른 사람이 쓴 카드가 있을 수 있습니다. 화면은 카드 글을 글자로만 넣고(`textContent`), 서버는 카드 글을 명령이나 경로로 쓰지 않습니다.
- **플러그인 형식을 일부만 확인했습니다.** 실제 보드 파일 두 개와 플러그인 parser의 요약을 근거로 했습니다. 한국어로 표시되는 완료 칸 표기, 칸의 최대 장수 표기, 여러 줄 카드가 실제로 기록되는 형태는 확인하지 못했습니다. 읽지 못하는 줄은 건너뜁니다.
- **링크가 열리는지 화면에서 확인하지 못했습니다.** `obsidian://` 주소를 브라우저와 데스크톱 앱에서 누른 결과는 #2 때부터 확인되지 않은 항목입니다([#4](https://github.com/inkme9/thync/issues/4)).
- **상위 폴더가 심볼릭 링크로 바뀌는 경우는 막지 못합니다.** vault 출처와 같은 한계입니다.
