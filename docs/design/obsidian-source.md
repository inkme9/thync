# Obsidian vault 출처

이슈: [#2](https://github.com/inkme9/thync/issues/2)

## 결정

`thync/sources/obsidian.py`가 설정한 vault 폴더를 직접 읽습니다. Obsidian 앱이나 플러그인을 거치지 않습니다. 수집 구간 안에 수정된 `.md` 파일마다 노트 하나를 돌려주고, `graph.build_graph()`가 이를 노드와 연결로 넣습니다.

### 설정

```json
{
  "sources": ["claude_code", "codex", "github", "jira", "notion", "obsidian"],
  "obsidian_vaults": [{"path": "~/vault", "profile": "회사"}]
}
```

- `sources`의 기본값에 `obsidian`을 넣습니다. `obsidian_vaults`가 비어 있으면 아무것도 읽지 않으므로, 기존 설정 파일은 고치지 않아도 지금과 같이 동작합니다.
- `profile`은 `회사` 또는 `개인`입니다. 생략하거나 다른 값을 쓰면 `개인`입니다.
- `path`가 폴더가 아니거나 읽을 수 없으면 그 vault는 건너뜁니다.

### 읽는 범위

- vault 아래의 `.md` 파일 가운데 파일 수정 시각이 최근 30일(`MAX_DAYS`) 안인 것을 찾습니다. 화면에서 고른 기간으로는 `build_graph()`가 다시 거릅니다.
- 이름이 `.`으로 시작하는 폴더(`.obsidian`, `.trash` 등)와 칸반 카드 폴더(`CARDS_DIR`)는 들어가지 않습니다. 카드 폴더를 vault 안에 두면 카드 파일이 노트로 한 번 더 보이기 때문입니다.
- 심볼릭 링크는 따라가지 않고, 링크인 파일도 읽지 않습니다. vault 밖의 파일이 읽히지 않게 하기 위해서입니다.
- 수정 시각이 최근인 순서로 vault 전체에서 최대 100개까지만 씁니다. Notion 출처의 상한과 같습니다.
- 파일마다 앞쪽 256KB까지만 읽습니다.
- 결과는 30초 동안 재사용합니다. 화면이 2초마다 그래프를 조회하므로 조회할 때마다 vault를 훑지 않게 합니다.

### 본문에서 뽑는 것

본문 문장은 저장하지 않고, 아래 네 가지만 뽑아 남깁니다. 코드 블록(```` ``` ````으로 감싼 부분)과 인라인 코드는 먼저 지우고 찾습니다.

| 대상 | 인식하는 형태 | 그래프에 넣는 방식 |
| --- | --- | --- |
| 노트 링크 | `[[노트]]`, `[[폴더/노트]]`, `[[노트\|표시 이름]]`, `[[노트#제목]]`, `![[노트]]` | 같은 vault에서 파일 이름이 같은 노트가 수집 구간 안에 있으면 두 노트를 연결합니다. 대소문자는 구분하지 않습니다 |
| 태그 | 본문의 `#태그`, 머리말(frontmatter)의 `tags:` | 같은 vault의 구간 안 노트 두 개 이상이 같은 태그를 가지면 태그 노드 하나를 만들어 그 노트들과 연결합니다. 대소문자는 구분하지 않습니다 |
| Jira 키 | 제목과 본문의 `ABC-123` | 접두어가 브랜치 이름이나 배정 티켓에서 확인된 경우에만 키로 봅니다(기존 규칙). 티켓과 연결하고, 첫 키의 작업 단위에 노트를 넣습니다. 제목의 키가 본문의 키보다 앞섭니다 |
| PR 주소 | `https://github.com/<소유자>/<저장소>/pull/<번호>` | `pr:<주소>` 노드와 연결합니다. 그 PR 노드가 없으면 만듭니다 |

- 노트 하나에서 Jira 키와 PR 주소는 각각 앞에서부터 10개까지만 씁니다. 목록 노트 하나가 그래프를 덮지 않게 하기 위해서입니다.
- `#123`처럼 숫자만 있는 것과 `# 제목`은 태그가 아닙니다. `https://example.com/#top`의 `#top`처럼 공백 뒤에 오지 않는 `#`도 태그로 보지 않습니다.

### 노드

| 노드 | id | 종류(`kind`) | `kind_label` |
| --- | --- | --- | --- |
| 노트 | `obsidian:<vault 폴더 이름>:<vault 기준 경로>` | `dailyNote` | Obsidian 노트 |
| 태그 | `obsidian-tag:<vault 폴더 이름>:<태그>` | `concept` | Obsidian 태그 |

- 노트의 이름은 확장자를 뺀 파일 이름입니다.
- 노트의 `url`은 `obsidian://open?vault=<vault 폴더 이름>&file=<vault 기준 경로>`입니다. [Obsidian URI 문서](https://help.obsidian.md/uri)의 `open` 형식이고, 값은 URI 인코딩합니다.
- 작업 단위는 Notion 페이지와 같은 규칙입니다. Jira 키가 있으면 그 티켓(또는 에픽)의 작업 단위이고, 없으면 노트 자신이 작업 단위입니다.
- 태그 노드와, 노트 때문에 새로 생긴 PR 노드는 그것을 처음 연결한 노트의 작업 단위에 넣습니다. 이미 있던 PR 노드의 작업 단위는 바꾸지 않습니다.
- 세션 로그를 쓰는 동안에는 노트가 활동의 출처가 되지 않고 노드만 더합니다. Notion, 커밋, 티켓과 같습니다(`graph.py`의 `touch()`).

## 치르는 비용

- **파일 수정 시각에 의존합니다.** 동기화 도구나 일괄 편집이 수정 시각을 바꾸면 내가 고치지 않은 노트도 잡힙니다. Obsidian은 누가 고쳤는지 기록하지 않으므로 Notion의 `notion_user_id` 같은 선별 방법이 없습니다.
- **30초까지 늦게 보입니다.** 재사용 시간 때문입니다.
- **링크는 파일 이름으로만 찾습니다.** 같은 이름의 노트가 여러 폴더에 있으면 구간 안에 있는 그 이름의 노트 모두와 연결합니다. Obsidian이 경로로 구분하는 경우까지 따라가지 않습니다.
- **머리말의 `tags:`는 흔한 세 가지 형태만 읽습니다.** `tags: [a, b]`, `tags: a, b`, 그리고 줄마다 `- a`로 쓰는 목록입니다. 표준 라이브러리에 YAML 해석기가 없기 때문입니다.

## 남는 위험

- **노트마다 칸반 카드가 생깁니다.** Jira 키가 없는 노트는 자신이 작업 단위가 되고, 작업 단위마다 카드가 하나 생깁니다. 일주일에 노트를 많이 고치면 카드가 그만큼 늘어납니다. Notion 페이지도 같은 방식이며, 이 변경에서 바꾸지 않습니다.
- **본문을 읽습니다.** 이 컴퓨터 안에서만 읽고, 그래프에는 제목, 태그, 뽑은 키와 주소만 들어갑니다. 제목과 태그는 `GET /graph.json`으로 화면에 나가므로, 접근 토큰을 가진 사람은 볼 수 있습니다. `docs/security.md`에 적습니다.
- **큰 vault의 탐색 시간.** 30초마다 vault 전체의 파일 정보를 읽습니다. 본문은 구간 안의 최대 100개만 읽습니다. 노트가 수만 개인 vault에서 걸리는 시간은 재지 않았습니다.
- **vault 폴더 이름이 Obsidian에 등록된 vault 이름과 다르면 링크가 열리지 않습니다.** Obsidian은 보통 폴더 이름을 vault 이름으로 씁니다.
